## 1. 분석 기준

2026-10-26~2026-10-28의 기본 요구사항과 [2026-11-02 범위 확정](2026-11-02.md)을 반영했다. 기획 자료는 프로젝트의 발표 자료와 세부 기능 목록이며, 분석 대상은 SSH TUI·CLI·MCP로 이용하는 다중 사용자 커뮤니티다. 본 문서는 요구사항이며 현재 구현 완료 상태를 뜻하지 않는다.

## 2. 문제 정의

### 2.1 개발 배경과 문제

터미널에서 작업하는 개발자는 커뮤니티나 채팅을 이용할 때 웹브라우저·별도 앱으로 이동해야 한다. 화면 전환과 작업에 무관한 알림은 작업 흐름을 끊을 수 있다. AI 에이전트 등 터미널 기반 도구를 사용하는 개발자가 터미널 안에서 교류할 수 있도록 서비스를 기획했다.

### 2.2 시스템 목표

Terminal-World는 SSH TUI·CLI·MCP로 이용하는 개발자 커뮤니티다. 기존 개인 공간·채팅·게시판·집중 기능과 Skills 게시판을 유지하고, 프로젝트·공모전 팀원 모집 및 중·소규모·신생 오픈소스 이슈 탐색을 제공한다. CLI는 명령 기반 이용을, MCP는 사용자가 허용한 범위의 AI 도구 연동을 지원한다. 이슈 선택 이후의 기여는 GitHub에서 수행한다.

| 목표 ID | 목표 | 연결되는 기능 |
|---|---|---|
| G-01 | 전용 앱이나 웹브라우저로 전환하지 않고 서비스에 진입 | SSH 접속, 게스트 탐색, 인증 |
| G-02 | 개발자로서 자신을 표현하고 공통 관심사를 발견 | 프로필, 개인 공간, 공간 탐색, 방명록 |
| G-03 | 개발자 사이의 실시간 교류와 지속적인 정보 공유 | 채팅, 게시글, 댓글, 공지 |
| G-04 | 커뮤니티에 머무르면서 집중·자리 비움을 구분 | 집중시간 기록·추적·일별 랭킹, 자리 비움 상태 |
| G-05 | 작업 중인 명령줄·AI 도구에서 동일한 커뮤니티 기능 이용 | CLI, MCP, 공통 권한·데이터 |
| G-06 | 관심과 기술에 맞는 오픈소스 기여 기회 발견 | 이슈 탐색, AI 설명, GitHub 원문 연결 |
| G-07 | 함께 참여할 프로젝트·공모전과 팀원 발견 | 모집글·조건 검색·마감·저장 |

## 3. 시스템 경계와 범위

### 3.1 경계

시스템은 SSH 접속 후 제공되는 커뮤니티 화면, 계정·권한 관리, 공간·콘텐츠 관리, 실시간 교류, 집중 기록과 데이터 보존을 담당한다. 배포하는 CLI 클라이언트와 MCP 서버도 시스템에 포함한다. 사용자의 SSH 클라이언트·터미널 에뮬레이터·MCP 호스트·네트워크, GitHub 및 외부 AI 제공자는 시스템 경계 밖이다. 시스템은 GitHub 공개 이슈 조회와 AI 설명 제공을 담당하며 GitHub 계정으로 이슈·PR을 작성하거나 코드를 변경하지 않는다.

개인 터미널은 프로필과 콘텐츠를 표현하는 **개인 공간**이다. 회원은 SSH 접속 후 서비스 내부에서 아이디·비밀번호로 로그인한다.

### 3.2 기본 범위

- SSH 접속, 게스트 둘러보기, 회원가입·로그인·로그아웃
- 회원별 프로필과 개인 공간, 꾸미기, 다른 사용자 공간 방문, 방명록
- Lobby의 접속자·공지 확인, Cafe의 게시글·댓글, RoofTop의 실시간 채팅
- Focus Room의 집중시간 기록·추적·하루 누적 시간·일별 랭킹
- Living Room의 자리 비움 상태 표시
- 사용자 간 데이터 공유, 영속 저장 및 권한에 따른 접근 제한
- 회원의 게시글·댓글·방명록·채팅 신고와 관리자 검토
- CLI·MCP를 통한 동일 기능 이용과 연동 자격 관리
- 공개 오픈소스 이슈 탐색·AI 설명·원문 연결
- 프로젝트·공모전 모집글 작성·조건별 탐색·마감·관심 글 저장

## 4. 액터와 권한

최초·추가 관리자 지정과 권한 회수는 서비스 운영자만 별도 운영 절차로 처리한다. 일반 관리자는 다른 회원의 권한을 변경할 수 없다. 권한을 회수하면 모든 기존 세션에서도 관리자 작업을 거부한다. 계정·로그인 상태와 일반 회원 권한은 유지한다.

관리자의 콘텐츠 삭제 기준은 다음과 같다.

- 스팸·도배, 위협·혐오·괴롭힘, 타인 개인정보 무단 공개, 불법 콘텐츠를 삭제한다. 단순한 의견 차이나 운영 비판은 삭제 사유가 아니다.
- 관리 목적으로 삭제할 때는 사유를 입력하고 처리 관리자·대상 식별자·처리 시각·사유를 기록한다. 본인 작성물이나 소유 공간의 방명록을 삭제할 때는 회원 권한을 적용한다.
- 삭제 이력의 보존 기간과 계정 식별정보 처리는 5절의 기록 보존 기준을 따른다.

| 행위 | 게스트 | 회원 | 관리자 |
|---|---|---|---|
| 공개 프로필·개인 공간·게시글·댓글·방명록·공지·접속자·랭킹 조회 | 허용 | 허용 | 허용 |
| 회원가입·로그인 | 허용 | 로그인 상태에서는 불필요 | 동일 |
| 자신의 프로필·개인 공간 편집 | 불가 | 허용 | 자신의 것만 허용 |
| 게시글·댓글·방명록 작성, 채팅 조회·참여 | 불가 | 허용 | 회원 권한과 동일 |
| 집중 기록 저장 | 불가 | 자신의 기록만 허용 | 자신의 기록만 허용 |
| 게시글·댓글 수정·삭제 | 불가 | 본인 작성분만 | 본인 수정·삭제 및 부적절한 타인 콘텐츠 삭제 |
| 방명록 수정 | 불가 | 본인 작성분만 | 본인 작성분만 |
| 방명록 삭제 | 불가 | 작성자 또는 대상 개인 공간 소유자 | 회원 권한 및 부적절한 콘텐츠 삭제 |
| 부적절한 채팅 메시지 삭제 | 불가 | 불가 | 허용 |
| 공지 작성·수정·게시 종료 | 불가 | 불가 | 허용 |
| 게시글·댓글·방명록·채팅 신고 | 불가 | 사유를 포함하여 허용 | 회원 권한과 동일 |
| 접수된 신고 검토 | 불가 | 불가 | 허용 |
| 전체 삭제 이력 조회 | 불가 | 불가 | 허용 |
| 본인 신고 상태·결과·처리 사유 조회 | 불가 | 본인 신고만 | 본인 신고 및 검토 권한 |

공개 이슈·AI 설명·모집글 조회는 게스트에게 허용한다. 모집글 쓰기·마감은 작성 회원에게, 관심 모집글 저장·목록 조회는 본인에게만 허용한다. 관리자는 기존 콘텐츠 삭제·신고 검토 규칙을 모집글에도 적용한다. CLI·MCP는 독립적인 권한 주체가 아니며 호출 계정과 허용 범위의 교집합으로 실행한다.

프로필·개인 공간·게시글·댓글·방명록에는 비공개·회원 전용·개별 비밀글 설정을 제공하지 않는다. 다른 회원에게 신고 내역과 신고자 정보를 공개하지 않는다.

개인 공간 삭제 후 남은 타인 방명록은 별도 공개 보관 목록에 표시한다. 대상은 ‘탈퇴한 사용자의 공간’으로 표시하며 프로필·공간을 복원하거나 새 방명록을 받지 않는다. 기존 작성자의 수정·삭제와 관리자의 부적절한 글 삭제만 허용한다. 같은 이름으로 가입한 새 계정에는 기존 권한을 넘기지 않는다.

집중 구간의 시작·중단 시각과 경과 시간은 본인만 조회한다. 관리자는 타인의 상세 기록을 조회할 수 없다. 일별 랭킹은 닉네임·순위·해당 날짜의 누적 시간을 게스트에게도 공개한다.

## 5. 기능 요구사항

| ID | 요구사항 | 목표 | 유스케이스 |
|---|---|---|---|
| FR-01 | SSH 클라이언트로 서비스 전용 앱 설치 없이 접속한다. 성공 시 진입 화면을 표시하고 실패 시 이유를 안내한다. | G-01 | UC-01 |
| FR-02 | 게스트는 4절의 공개 정보를 조회한다. 쓰기·채팅 조회·참여에는 로그인이 필요함을 안내한다. | G-01 | UC-01 |
| FR-03 | 아이디·닉네임·비밀번호로 가입한다. 5.3절의 입력·중복 기준을 검사하고 유효한 입력으로 계정·개인 공간을 생성한 뒤 자동 로그인한다. | G-01 | UC-02 |
| FR-04 | 아이디·비밀번호로 중복 로그인하고 세션별로 로그아웃한다. 인증·재시도 제한은 5.3절, 비밀번호 변경·세션 종료는 5.6절을 따른다. 인증 실패·로그아웃 세션에는 회원 권한을 부여하지 않는다. | G-01 | UC-02 |
| FR-05 | 가입 완료 시 회원이 소유하는 개인 공간 하나를 제공한다. 계정과 개인 공간이 모두 생성되어야 가입을 완료한다. | G-02 | UC-02 |
| FR-06 | 공용·개인 공간을 구분하는 2.5D 월드를 기본으로 제공하고 목록 탐색도 항상 제공한다. 방향키로 이동·선택하고 Enter로 진입하며 Esc로 탐색에 복귀한다. 두 방식은 같은 공개 공간·방문 권한을 따르며 방문으로 편집 권한을 얻지 않는다. 확대·축소는 제공하지 않는다. 화면 기준은 5.13절을 따른다. | G-02 | UC-03 |
| FR-07 | 회원은 자신의 프로필·개인 공간을 편집·저장한다. 저장 결과는 재접속과 다른 사용자의 조회에 반영하며 타인 공간 편집은 거부한다. 프로필 항목·길이·URL은 5.10절을 따른다. | G-02 | UC-04 |
| FR-08 | 개인 공간에 자기소개·기술 스택·상태·ASCII 아트·컬러 테마를 표현한다. ASCII 아트는 직접 입력·프리셋 모두 최대 40열×12줄이며 출력 가능한 ASCII와 줄바꿈만 허용한다. 테마는 다크·라이트·그린·앰버 4종, 기본값은 다크다. 고정 레이아웃과 저장 전 미리보기를 제공한다. 임의 색상 코드·영역 이동·크기 조절은 제공하지 않으며 미리보기는 저장 전 공개 상태를 바꾸지 않는다. 잘못된 문자·크기 초과는 정정을 안내하고 잘라 저장하지 않는다. | G-02 | UC-04 |
| FR-09 | 회원은 다른 회원의 개인 공간에 방명록을 작성한다. 작성자·내용·작성 시각을 표시하고 수정은 작성자만 허용한다. 삭제·공간 삭제 후 공개 보관·권한은 4절을 따른다. 입력 기준은 5.11~5.12절을 적용한다. | G-02 | UC-05 |
| FR-10 | Cafe에 자유·개발 질문·정보 공유·MCP·Skills·opensource·프로젝트/공모전 모집의 게시판 7개를 제공한다. 모집글의 추가 기준은 FR-31을 따른다. opensource 게시판의 사용자 작성글과 FR-29의 GitHub 이슈 목록은 구분한다. 글 목록·본문을 공개 조회하고 회원은 선택한 게시판에 글을 작성한다. | G-03 | UC-06 |

**FR-24 신고 접수 제한**

- 거부·중복 요청은 건수와 마지막 접수 시각을 바꾸지 않는다. 동시 요청에도 중복 접수·한도 초과를 방지한다.
- 검토 전 대상이 삭제되면 결과를 ‘조치 없음’, 사유를 ‘대상 삭제됨’으로 기록한다. 별도 푸시 없이 본인 신고 화면에서 결과를 확인한다.

### 5.1 공통 업무 규칙

- BR-01: 회원별 개인 공간은 하나이며 가입 완료 시 생성한다. 게스트는 개인 공간을 갖지 않는다.
- BR-03: 필수 텍스트는 공백만 입력할 수 없으며 초과 입력은 잘라 저장하지 않고 정정을 안내한다. 항목별 형식·길이는 5.3절·5.5절·5.10~5.12절과 FR-08을 따른다.
- BR-06: 집중시간은 목표 시간 없이 추적하며 5.2절의 중단·집계·중복 세션 규칙을 적용한다.

### 5.2 접속 상태와 집중시간 집계

**접속 상태**

- CLI·MCP의 단발 조회·작성 요청은 온라인·자리 비움이나 집중시간을 자동 생성하지 않는다. 지속 세션을 명시적으로 열 때만 아래 접속 상태에 참여한다. 집중 시작은 지속 연결을 소유하는 세션에서만 허용하며 세 인터페이스 모두 같은 단절 규칙을 적용한다.

- 접속자 목록에는 회원을 계정당 한 번, 게스트를 인원수로 표시한다. 정상 접속·종료·공간 이동을 반영하고 비정상 단절을 감지한다. 재접속은 Lobby에서 시작한다.
- 접속 세션이 하나라도 있으면 온라인이다. 모든 접속 세션이 Living Room에 있을 때만 자리 비움이며, 세션이 없으면 오프라인이다. 일부 세션 종료 시 남은 세션으로 다시 판단한다.

**집중시간**

- 시작부터 중단까지 경과 시간을 추적하고 현재 구간·당일 누적 시간을 시간·분·초로 표시한다. 목표 시간 설정·만료·기록 없이 폐기하는 취소 기능은 제공하지 않는다.
- 진행 중인 집중 구간은 계정당 하나이며 동시 시작으로 중복 생성하지 않는다. 같은 계정의 어느 세션에서든 확인·중단할 수 있다.
- 중단 시 구간별 초 미만을 버림하여 정수 초로 저장·누적한다. 같은 구간은 한 번만 합산한다.
- 추적을 시작한 세션이 끊기면 다른 세션 접속 여부와 무관하게 중단하고 마지막 연결 확인 시점까지만 기록한다. 다른 세션의 단절만으로는 중단하지 않으며 재접속 시 자동 재개하지 않는다.
- 한국 시간(Asia/Seoul) 자정을 기준으로 구간을 날짜별로 분할한다. 당일 누적 시간이 같으면 공동 순위이며 다음 순번은 동률 인원만큼 건너뛴다(1위·1위·3위).

### 5.3 계정 입력 및 인증 정책

| 항목 | 입력 기준 |
|---|---|
| 아이디 | ASCII 영문·숫자·밑줄(`_`)·대시(`-`), 4~20자, 중복 불가 |
| 닉네임 | NFC 정규화 후 완성형 한글·ASCII 영문·숫자·밑줄·대시, 2~12자, 중복 불가. 독립 자모 불가 |
| 비밀번호 | 10~24자, 출력 가능한 ASCII 전체(U+0021~U+007E), 붙여넣기 허용. 소문자·대문자·숫자·특수문자 중 최소 세 종류 포함 |

- 닉네임은 NFC 정규화한 값을 저장·표시하며 완성형 한글과 허용 ASCII 문자를 각각 1자로 센다.
- 아이디·닉네임은 표시 시 영문 대소문자를 유지하고 중복 검사에서는 구분하지 않는다. 아이디 로그인도 구분하지 않으며 비밀번호는 대소문자를 구분한다.
- 비밀번호의 특수문자는 허용 ASCII에서 영문·숫자를 제외한 전체다. 따옴표·역슬래시·백틱도 허용한다. 공백·탭·줄바꿈·제어문자·비ASCII 문자는 거부한다.
- 가입 완료 시 자동 로그인한다. 계정 기준 연속 5회 로그인 실패 시 5분간 제한하며 성공 또는 제한 시작 후 5분 경과 시 실패 횟수를 초기화한다. 제한 중 요청은 거부하고 종료 시각을 연장하지 않는다.
- 입력이 없어도 로그인 상태를 유지한다. 연결 종료 후 재접속에는 인증이 필요하다.

### 5.4 복구·분실·탈퇴 정책

**계정 복구**

- 이메일 연동 없이 아이디·유효한 복구 코드로 본인 확인 후 새 비밀번호를 설정한다. 새 비밀번호는 5.3절, 코드 발급·입력·제한은 5.5절을 따른다.
- 복구 성공 시 모든 기존 세션과 CLI·MCP 연동 자격을 무효화하고 사용 코드를 폐기한 뒤 새 코드를 발급한다. 로그인 회원의 코드 재발급에는 현재 비밀번호 확인이 필요하다.
- 아이디 검색·비밀번호 조회·관리자 임의 초기화는 제공하지 않는다. 비밀번호와 복구 코드를 모두 분실하면 복구할 수 없다.

**회원 탈퇴**

- 현재 비밀번호 재확인·삭제 및 보존 범위 안내·최종 확인 후 탈퇴한다. 모든 세션·복구 코드·CLI/MCP 연동 자격을 무효화하고 로그인·복구를 차단한다.
- 프로필·개인 공간·집중 기록·관심 모집글 저장을 삭제하고 랭킹에서 제외한다. 작성 모집글은 마감하며 남는 본문은 게시글 보존 규칙을 따른다. 남는 게시글·댓글·방명록·채팅의 작성자는 ‘탈퇴한 사용자’로 표시한다.
- 계정 관리 개인정보·식별 연결은 탈퇴 후 90일 기한까지 완전 삭제한다. 백업·운영 로그·개인정보 삭제 요청 기록에도 같은 기한을 적용한다(5.7절·5.9절).
- 아이디·닉네임은 탈퇴 후 90일 동안 재사용을 제한하고 이후 허용한다. 새 계정에 기존 작성물·기록·권한을 승계하지 않는다.
- 계정 연결을 제거한 게시글·댓글·방명록 본문은 유지하며 탈퇴를 이유로 자동 검사·수정·삭제하지 않는다. 채팅은 전송 시각부터 14일 기한을 적용한다. 원글 삭제 시 댓글 동시 삭제·관리자 삭제 권한은 유지한다.
- 삭제된 공간의 타인 방명록은 4절의 공개 보관·권한을 따른다. 본문 개인정보의 별도 삭제 요청은 5.8절로 처리한다.

### 5.5 복구 코드 형식·표시·시도 제한

- **생성:** 암호학적으로 안전한 무작위 32자리다. 허용 문자는 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`이며 혼동 문자 `I`, `L`, `O`, `0`, `1`은 제외한다. 4자리씩 8묶음을 대시로 구분한다.
- **입력:** 대소문자를 구분하지 않고 구분용 대시 생략·붙여넣기를 허용한다. 검증 시 같은 표준 형태로 변환한다.
- **표시:** 가입·재발급·복구 성공 직후 화면에서만 전체 표시한다. 아이디와 함께 보관하도록 안내하고 보관 확인 후 화면을 종료한다. 이후 전체 재조회는 제공하지 않는다.
- **저장:** 검증용 값만 저장하며 코드 원문은 영구 저장하거나 로그에 남기지 않는다.
- **유효성:** 시간 만료는 없다. 사용·재발급·탈퇴 시 무효화하며 복구·재발급 성공 시 새 코드를 발급한다. 동일 코드의 동시 복구는 한 번만 성공한다.
- **시도 제한:** 계정 기준 연속 5회 실패 시 30분간 제한한다. 성공 또는 제한 시작 후 30분 경과 시 횟수를 초기화하며 제한 중 요청은 종료 시각을 연장하지 않는다. 일반 로그인과 실패 횟수·제한을 분리한다.
- **실패 안내:** 존재하지 않는 아이디와 잘못된 코드에는 동일한 복구 실패 안내를 사용한다.

### 5.6 일반 비밀번호 변경 및 세션 처리

- 로그인 회원은 현재 비밀번호를 확인하고 5.3절에 맞는 새 비밀번호를 설정한다.
- 변경 성공 시 현재 세션과 복구 코드는 유지하고 다른 세션과 모든 CLI·MCP 연동 자격은 무효화한다. 코드를 교체하려면 재발급을 요청한다.
- 종료되는 세션이 집중 추적의 시작 세션이면 집계를 중단한다. 남은 세션에 따라 접속·자리 비움 상태를 다시 판단한다(5.2절).

### 5.7 백업·복구 및 보존 사본 처리

- 매일 1회 백업하고 생성 시점부터 7일 보관 후 삭제한다. 운영 데이터와 분리하며 서비스 운영자만 접근한다.
- 복구 후 서비스 재개 전에 삭제·탈퇴·보존 만료를 재적용하고 완료를 확인한다. 원글·댓글·관리자 삭제 콘텐츠, 탈퇴 삭제 대상, 만료된 채팅·신고·삭제 이력을 다시 노출하지 않는다.
- 탈퇴 계정의 개인정보·식별 연결은 기존 백업을 포함해 탈퇴 후 90일 기한까지 삭제한다. 백업 생성·복구로 기한을 연장하지 않는다.
- 삭제 콘텐츠의 본문 사본은 증거용으로 별도 보관하지 않는다. 삭제 전 백업에 포함된 본문에도 7일 보관·운영자 전용 접근·복구 후 삭제 재적용을 적용한다.

### 5.8 별도 개인정보 삭제 요청 처리

- 운영자 전용 창구에서 대상 콘텐츠·개인정보 위치·사유를 접수하고 요청자와 개인정보의 관련성을 확인한다. 불필요한 신분증은 수집하지 않는다.
- 검토 후 삭제 필요성이 확인되면 대상 콘텐츠를 삭제하며 타인 본문을 임의 수정하지 않는다. 원글·댓글 동시 삭제, 관리자 삭제 사유·이력 규칙을 적용하고 보관 방명록도 대상으로 한다.
- 접수 후 7일 이내 1차 답변, 원칙적으로 30일 이내 실제 처리 결과·사유를 안내한다.
- 삭제 결과는 백업 복구 후 서비스 재개 전에 재적용한다. 처리 기록은 5.9절을 따르며 법령상 별도 의무는 우선 적용한다.

### 5.9 운영 로그·개인정보 삭제 요청 처리 기록

| 기록 | 내용 | 보존·접근 |
|---|---|---|
| 운영 로그 | 시각·사건 종류·성공/실패·오류 코드·아이디·닉네임·IP | 발생 시점부터 14일, 운영자 전용 |
| 개인정보 삭제 요청 처리 기록 | 대상 식별자·최소 확인 결과·처리 결과·사유·시각 | 처리 중 유지, 완료 시점부터 90일, 운영자 전용 |

- 운영 로그에 비밀번호·복구 코드·연동 자격 원문·콘텐츠 본문·입력 원문을 남기지 않는다. 비밀정보·원문이 섞인 오류 내용 대신 오류 코드를 기록한다. 계정 식별값이 없는 경우 해당 값을 만들어 넣거나 다른 계정 값으로 대체하지 않는다.
- 개인정보 삭제 요청 기록은 표의 최소 항목만 보관하며 불필요한 신분증 사본은 보관하지 않는다.
- 각 보존 기한이 지나면 기록을 삭제한다. 탈퇴 계정의 개인정보·식별 연결은 기록 보존과 별개로 탈퇴 후 90일 기한까지 제거한다.
- 복구 후 서비스 재개 전 만료·탈퇴 식별정보 삭제·개인정보 삭제 요청 결과를 재적용하며 보존 기한을 초기화하지 않는다.

### 5.10 프로필 항목·길이·프로젝트 URL

닉네임 외 프로필 항목은 선택이며 비워도 저장·서비스 이용이 가능하다. 닉네임은 5.3절을 따른다.

| 선택 항목 | 입력 기준 |
|---|---|
| 자기소개 | 최대 500자 |
| 기술 스택 | 최대 10개, 항목당 최대 20자 |
| 현재 상태 문구 | 최대 80자. 자동 접속·자리 비움 상태와 별개 |
| 프로젝트 URL | HTTPS 주소 최대 1개, 최대 2,048자 |

글자 수는 NFC 정규화 후 코드포인트로 센다. 기술 스택 개수와 항목별 길이를 각각 검사하며 한도를 넘으면 잘라 저장하지 않고 수정을 요청한다. 프로젝트 URL은 표시만 하며 외부 정보를 자동 수집하지 않는다. HTTPS 이외 주소는 거부한다. ASCII 아트·테마는 FR-08을 따른다.

### 5.11 콘텐츠 입력 길이

| 항목 | 최대 길이 |
|---|---:|
| 게시글·공지 제목 | 100자 |
| 게시글·공지 본문 | 10,000자 |
| 댓글·방명록 | 1,000자 |
| 채팅 메시지 | 500자 |
| 신고 사유·관리자 처리 사유 | 1,000자 |

길이는 항목별로 NFC 정규화 후 코드포인트로 세며 최대값까지 허용한다. 필수 항목에 공백만 입력하거나 최대 길이를 넘으면 수정을 요청하며 잘라 저장하지 않는다. 보관 방명록 수정도 같은 기준으로 검사한다. 계정·프로필·ASCII 아트의 형식·한도는 각각 5.3절·5.10절·FR-08을 따른다.

### 5.12 일반 텍스트 문자·줄바꿈·표시

- 한글·영문·숫자·기호·이모지를 허용하고 탭·터미널 제어문자·ANSI 제어 시퀀스는 거부한다. 붙여넣기·수정에도 같은 검증을 적용한다.
- 제목·기술 스택 항목·상태 문구·URL·채팅은 한 줄 입력이며 줄바꿈을 거부한다. 자기소개·게시글/공지 본문·댓글·방명록·사유는 줄바꿈을 허용한다.
- 화면 폭을 넘으면 한글·이모지의 표시 폭을 고려해 자동 줄바꿈·스크롤로 표시한다. 표시용 줄바꿈이나 잘림으로 저장 원문을 바꾸지 않는다.
- 계정·ASCII 아트에는 별도 허용 문자·길이를 적용하고 URL에는 HTTPS 형식을 적용한다. 사용자 입력의 ANSI 거부와 서비스 자체의 테마·화면 제어 출력은 구분한다.

### 5.13 지원 환경·화면·문자 호환

- macOS·Linux의 OpenSSH, Windows 11의 Windows Terminal+OpenSSH 조합을 지원한다.
- UTF-8·256색은 필수이며 이미지 지원은 요구하지 않는다.
- 최소 화면은 **80열×24행**, 2.5D 월드 권장은 **120열×30행 이상**이다. 목록 탐색은 모든 화면 크기에서 제공한다.
- 한글·이모지 입력·표시를 지원한다. 글꼴 모양 차이는 허용하되 필수 텍스트·조작 안내가 잘리거나 입력 영역과 겹치지 않아야 한다.

### 5.14 성능 요구사항 제외 결정

응답 시간·동시 접속 규모·조회/채팅 부하, 상태 반영·비정상 단절 감지 시간 상한, RPO·RTO와 관련 성능 시험·인수 기준은 제외한다. 기능·보존·인증/신고 제한·집중 집계·백업 규칙은 해당 조항을 따른다.

### 5.15 CLI·MCP 기능 동등성과 권한

- 기존 UC-01~UC-14와 신규 UC-17~UC-18의 업무 동작을 CLI·MCP에서도 제공한다. 2.5D 애니메이션·키 입력·시각적 미리보기는 화면 그대로 복제하지 않고 공간 목록·현재 구성·변경 예정 값을 제공한다. 해당 동작의 인증·현재 비밀번호 확인·복구 코드 검증·최종 확인을 생략하지 않는다.
- CLI는 명령 도움말·비대화형 인수·파일/표준입력 및 구조화된 결과를 지원한다. 조회 목록은 이어받기 가능한 페이지 정보를 제공하며 오류와 결과 없음, 미확인 전송을 구분한다. 채팅 수신·집중 추적처럼 지속 연결이 필요한 동작은 명시적인 세션/구독으로 제공한다.
- MCP 호스트는 도구와 입력·출력 규격을 발견할 수 있다. CLI와 MCP는 같은 업무 기능을 호출하며 독자적인 데이터 사본이나 권한 예외를 갖지 않는다. 구체적 명령명·전송 방식·SDK는 설계 단계에서 정한다.
- 계정 인증과 사용자 동의를 거쳐 CLI·MCP 연동 자격을 부여한다. 허용 작업 범위·만료 시각·회수 상태를 관리하고 회원은 본인 연동을 조회·회수한다. 조회·게시/수정·삭제·관리자 작업을 구분하며 허용되지 않은 작업은 거부한다. 만료 기간의 수치는 설계 시 결정하되 무기한 자격은 발급하지 않는다.
- 가입·복구·현재 비밀번호 확인 등 민감 입력은 사용자 직접 입력을 지원하고 AI 모델 컨텍스트·명령 이력·일반 로그에 자격 원문을 노출하지 않는다. 호스트가 보호된 입력을 제공하지 못하면 사용자 인증 절차로 인계하며 모델에 비밀번호를 요구하지 않는다.
- 쓰기 작업은 사용자가 명시적으로 허용한 대상·작업 범위 안에서 수행하고 결과를 확인할 수 있어야 한다. 삭제·탈퇴 등 기존 최종 확인 요구는 그대로 적용한다. 자격 보유만으로 무제한 자율 게시 권한을 부여하지 않는다.
- 관리자 권한 회수는 연동 자격이 남아 있어도 즉시 관리자 작업에 반영한다. 로그아웃은 해당 세션을 종료하며 자격 자체 회수는 별도 동작이다. 복구·비밀번호 변경·탈퇴 시 무효화는 5.4~5.6절을 따른다.
- 재시도로 같은 쓰기 요청을 중복 처리하지 않으며 결과가 불명확하면 완료를 단정하지 않는다. API로 같은 기능을 호출해 기존 인증·신고 제한을 우회하지 못한다. 외부 게시글·이슈·AI 출력은 정보로 취급하며 추가 도구 실행 지시나 사용자 승인으로 취급하지 않는다.

### 5.16 오픈소스 이슈 탐색 기준

- 공개 저장소 중 오픈소스 라이선스가 확인된 대상을 다룬다. 중·소규모와 신생 저장소를 우선하되 규모·신생·트렌드에 대한 검증된 시장 기준이 있다고 가정하지 않는다. 스타 수만으로 난이도·품질·활동성을 판정하지 않는다.
- 운영자는 규모 구간·신생 기간·추세 관찰 기간·선정 규칙을 설정하고 사용자에게 적용 기준과 근거 시점을 표시한다. 수치와 외부 조회 주기는 미확정 설계 항목이며 서비스 제공 전에 설정해야 한다. 기준이 없는 항목은 미분류로 표시하며 신생·트렌디로 단정하지 않는다.
- 언어·분야·관심 키워드는 사용자가 입력한다. 로컬 저장소·비공개 GitHub 데이터·사용자 코드를 자동 수집하지 않는다. GitHub 로그인이나 저장소 쓰기 권한은 이슈 탐색의 필수 조건이 아니다.
- 조회 자료는 저장소 URL·이슈 번호·제목·본문/참조 정보·라벨·상태·확인 시점으로 식별한다. 담당자·연결된 PR·최근 논의가 확인되면 표시하되 미확인을 참여 가능으로 단정하지 않는다. 선택 시 원문에서 최신 상태를 확인하도록 연결한다.
- 닫힘·삭제·접근 불가가 확인된 이슈는 현재 열린 후보에서 제외하고 기존 상세 요청에는 해당 상태를 안내한다. 외부 장애·요청 한도·자료 지연은 결과 없음과 구분하고, 마지막 확인 자료를 보이면 확인 시점과 최신 여부 미확인을 함께 표시한다.
- AI 설명은 공개 이슈 자료와 사용자가 지정한 탐색 조건을 근거로 생성한다. 요약·배경지식·추천 이유에 근거 링크·생성 시점·사용한 자료 시점을 표시하며, 예상 난이도·시간·기여 수락 가능성을 사실처럼 단정하지 않는다. 생성 실패·근거 부족은 설명 없음/미확인으로 표시한다.
- AI 사용은 이슈 이해와 추천 설명까지다. 이슈 배정·GitHub 댓글/PR 작성·저장소 복제·패키지 설치·코드 실행·원클릭 수정 준비·기여 후속 관리는 범위 밖이다.

### 5.17 프로젝트·공모전 모집 게시판

- 필수 항목은 제목·본문·유형(프로젝트/공모전/해커톤)·진행 상태 설명·모집 역할·필요 기술·참여 기간·예상 주당 시간·참여 방식(온라인/오프라인/혼합)·지원/연락 방식이다. 오프라인·혼합에는 지역을 입력한다. 기술 요구가 없으면 그 사실을 명시한다. 모집 마감일은 선택 항목이다.
- 제목·본문·선택 값 이외 상세 설명은 본문 길이 한도에 포함하며 기존 텍스트·URL 기준을 적용한다. 게시 전에 연락 방법을 포함한 전체 글이 공개됨을 안내한다. 일반 게시글·Skills 게시판에 모집 전용 필드를 요구하지 않는다.
- 상태는 모집 중·마감이다. 작성자가 마감하거나 지정한 마감 시각이 지나면 마감하고, 마감 글은 상태 필터로 조회할 수 있다. 지정 시각은 Asia/Seoul로 해석한다. 수정·삭제는 작성자, 부적절한 글 삭제와 신고 처리는 기존 권한을 따른다.
- 관심 글은 회원별 중복 없이 저장·해제하고 재접속 시 유지한다. 다른 회원·관리자는 개인 저장 목록을 조회하지 못한다. 글 삭제 시 연결된 저장을 제거하고 탈퇴 시 본인 저장을 삭제한다. 마감 상태는 저장 목록에도 반영한다.
- 지원은 글에 기재한 연락 방식으로 이루어진다. 지원자 접수·선발·쪽지·자동 매칭·팀 관리·협업 공간은 제공하지 않는다.
