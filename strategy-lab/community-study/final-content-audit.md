# 최종 콘텐츠 감사

검수일: 2026-10-30. 대상: `lanes/korea-commons.json`, 통합 `data.json`, `narrative.md`. UI·브라우저 동작은 범위 밖이다. 이 문서만 작성했으며 대상 원본은 수정하지 않았다.

## 판정: PARTIAL — 추천의 근거는 타당하나 일정과 진입 약속을 맞춰야 한다

새 추천인 **공동 제작 터미널 마을**은 두 산출물에서 일치한다. 회원 작품의 실행 → 변형 → 계보 → 공동 반영 → 다른 회원의 사용·반응을 중심에 두며, 개인 메모 도구로의 전환을 추천하지 않는다. 수요·재방문·경쟁 우위는 미검증 가설로 명시돼 있다. 아래 공식 원문 5개에서 최종 추천을 뒤집을 만한 사실 오류는 발견하지 못했다.

남은 중대한 정합성 문제는 **① 기존 도구 비교와 14일 파일럿의 일정 불일치**, **② 설치 없는 진입이라는 일부 단정과 제안 기술 경로 사이의 간극**이다. 근거를 검증된 사용자 수요로 과장하거나 점수를 성공확률로 표현하는 문제는 확인하지 못했다.

## 수정할 사항

### 1. 일정 원장을 하나로 통일해야 한다

**증거 위치**

- `data.json → roadmap[W02]`: 기존 방식/TUI 비교 실험, 충분하면 별도 앱 중단.
- `data.json → roadmap[W05–06]`: 14일 자유 파일럿.
- `data.json → experiments.protocol`: 비교 조건 경험 뒤 14일 자유 이용, 한 차례 공개 체험회 이후 개인 독려·과제·보상 없이 관찰.
- `narrative.md → 13절`: 2주는 첫 행동 관찰, 기존 도구와 순서 교차 비교는 **6주**, 운영자 공급 축소·후속 방문 관찰은 **7주**다.

현재 표현대로 두 계획을 동시에 수행하면, data의 자유 이용 관찰 기간에 narrative의 진행자 개입 비교 실험이 들어간다. 어떤 행동이 독려 없는 재방문인지 해석하기 어렵고, 독립 앱 개발 중단 여부를 판단하는 시점도 달라진다.

**최소 수정**: data의 순서를 단일 일정으로 채택한다면 narrative의 2주에 **수동·저충실도 프로토타입의 기존 도구 비교**를 명시하고, 5–6주는 온전히 14일 자유 이용으로 표시한다. 6주의 비교 행사는 제거하거나 별도 시점으로 옮긴다. 7주의 관찰은 파일럿 이후 보조 추적임을 명시한다. 반대로 6주 비교를 유지하려면 data의 단계·14일 관찰 시작·종료를 함께 바꾼다. 어느 경우든 시행 전 계획이며 이미 실시된 실험으로 표현하지 않는다.

### 2. “설치 없이”의 적용 범위를 작품 단위로 좁혀야 한다

**증거 위치**

- `data.json → ideas[id=world].reason/reasonToUse`: “설치·환경 설정 없이 같은 작품을 경험”.
- `narrative.md → 1절`: “설치 부담 없이 체험”. 8절은 새 런타임 설치 없는 체험을 검증 질문으로 적었다.
- `data.json → mvp.stack`: 기존 Ink 로컬 클라이언트 + 중앙 서비스로 먼저 검증하고, SSH 계층은 별도 선택한다.
- `data.json → meta.currentImplementation`과 `narrative.md → 3절`: 실제 SSH·다중 사용자 서비스는 구현 완료가 아니다.

로컬 클라이언트의 설치·실행 조건과 SSH 접속 경로가 확정되지 않아 **제품 최초 진입 전체가 설치 없이 동작한다는 약속은 아직 입증되지 않았다**. 작품마다 별도 런타임·의존성을 설치하지 않는다는 설계 목표와 첫 클라이언트 진입 비용은 구분할 필요가 있다.

**최소 수정**: 단정형 문구를 “**클라이언트 진입 뒤 작품마다 추가 런타임·의존성을 설치하지 않고 체험하는 것을 목표로 한다. 최초 접속·설치 부담은 비교 실험에서 확인한다**”로 통일한다. 가입 전 웹 예시가 있다면 그 경로 역시 제안임을 유지한다. 현재 설명된 제품 우위는 구현된 기능이 아니라 검증할 차이라는 표현을 유지한다.

## 통합 데이터와 전략의 일관성 확인

- **수량**: 사례 83, 심층 기록 29, 아이디어 9, 상위 콘셉트 3으로 배열 길이와 메타 값이 일치한다. 신규 lane은 사례 19·심층 기록 6이다. 중복 사례 ID와 존재하지 않는 심층 기록 참조는 발견하지 못했다. 아이디어·상위 콘셉트의 `refs/sourceIds`는 실제 사례 ID를 가리킨다.
- **범위**: 87개 등록 후보 = 사례 83 + 별도 접근 제한 4다. 83을 현재 활발한 독립 공동체의 수나 완전한 웹 전수 조사라고 부르지 않는다. 플랫폼·네트워크·행사·종료 조직이 섞였다는 설명도 일치한다.
- **URL 개수의 정의**: 151은 `communities[].sources[].url`의 고유 URL 수로 재현된다. 심층 기록의 추가 URL까지 포함하면 153이며 접근 제한 URL 4까지 포함하면 157이다. 151을 쓸 때는 “**83개 사례의 출처 URL 151개**”라고 범위를 밝히면 된다. 151개 모두 현재 본문 접근 성공이라는 주장은 확인하지 못했다.
- **점수**: 기본 가중치 합은 100이다. 가중 평균×20으로 재계산하면 공동 제작 마을 **74**, Commons Lab **68**, 리뷰 교환 클럽 **65**다. 점수는 가설적 상대 평가이며 성공확률이 아니라는 설명과 일치한다. 콘셉트 소개 순서가 곧 점수 순위라는 주장은 narrative에 없다.
- **추천과 MVP**: 단독 체험은 시작 가치를 제공하되 회원 간 사용·응답·후속 변형이 없으면 공동체 가설의 성공이 아니라는 경계가 일치한다. 제한된 작품 포맷, 검토 후 공용 반영, 버전·되돌리기·권리·신고를 핵심에 두며 범용 셸·무제한 코드 호스팅은 제외한다.
- **실험 수치**: 성인 8–12명, 시드 3개, 14일, 각 문턱과 운영 시간 상한은 앞으로 사전 합의할 제안이다. 벤치마크·측정 결과·통계적 인과 효과로 표현하지 않았다. narrative의 상세 질문과 data의 축약 질문은 같은 검증 목적을 가진다.
- **현재 구현**: 정적 소스의 로컬 프로토타입·원격 전달 없음·예시 계정 표시는 `src/cli.tsx`와 `src/App.tsx`에서 확인됐다. 신규 실행·리믹스·공동 세계를 이미 구현했다는 주장과 혼동하지 않는다. 앱 실행이나 네트워크 동작 시험을 한 것은 아니다.

## 통과 조건과 남은 공백

일정 원장과 설치 부담 표현을 정정하면, 검수 범위의 최종 전략을 제출 가능한 **조건부 제품 제안**으로 볼 수 있다. 지금의 공개 사례는 제안된 참여 구조의 선행 존재를 뒷받침한다. 한국 대학생의 실제 수요, 터미널 선택 이유, 공동 반영의 추가 가치, 14일 재방문, 운영 비용·안전성을 입증하지는 않는다. 이는 이미 명시된 후속 실험의 과제이며 추가 리서치 사례 수나 정량 점수로 대신할 수 없다.

UI 검수, 모든 링크 전수 접속, 실제 참가자 모집·인터뷰·파일럿은 이번 감사에서 수행하지 않았다.
